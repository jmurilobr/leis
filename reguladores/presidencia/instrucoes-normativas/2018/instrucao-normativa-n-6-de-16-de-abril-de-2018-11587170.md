# INSTRUÇÃO NORMATIVA Nº 6, DE 16 DE ABRIL DE 2018

<div class="texto-dou"><p class="subtitulo">INSTITUTO NACIONAL DE TECNOLOGIADA INFORMAÇÃO</p><p class="identifica"><strong class="dou-strong" >INSTRUÇÃO NORMATIVA Nº 6, DE 16 DE ABRIL DE 2018</strong></p><p class="ementa">Inclui o Item 6.4 no DOC-ICP-17.01, referente a requisitos para serviços de confiança de uso de chaves privadas.</p><p class="dou-paragraph" ><strong class="dou-strong" >O DIRETOR-PRESIDENTE DO INSTITUTO NACIONAL DE TECNOLOGIA DA INFORMAÇÃO,</strong>no uso das atribuições que lhe foram conferidas pelo inciso VI do art. 9º do anexo I do Decreto nº 8.985, de 8 de fevereiro de 2017, pelo art. 1º da Resolução nº 33, do Comitê Gestor da ICP-Brasil, de 21 de outubro de 2004, resolve:</p><p class="dou-paragraph" >Art. 1º O DOC-ICP-17.01, versão 1.0, passa a vigorar acrescido do item 6.4 com a seguinte redação:</p><p class="dou-paragraph" >"6.4. Requisitos para serviços de confiança de uso de chaves privadas</p><p class="dou-paragraph" >6.4.1. Definições para Interface de Serviços de Confiança</p><p class="dou-paragraph" >Deverá ser utilizado o protocolo TLS, definido pela RFC 5246, para comunicação com serviços de confiança.</p><p class="dou-paragraph" >Deverá ser utilizado o framework OAuth 2.0 (RFC 6749 e RFC 7636) para implementação da interface aos s erviços de confiança dos PSC.</p><p class="dou-paragraph" >Adicionalmente, poderá ser implementada outra interface para os serviços de confiança, desde que o PSC proveja o software necessário para possibilitar ao titular o uso das suas chaves privadas de forma segura.</p><p class="dou-paragraph" >6.4.2. Definições para URI de base para Serviços de Confiança</p><p class="dou-paragraph" >A URI de base - URI-base - definirá o estilo e formato dos endereços HTTPS de serviços de confiança.</p><p class="dou-paragraph" >A URI de base conterá número correspondendo à versão de API definida pela ICP-Brasil.</p><p class="dou-paragraph" >Este documento trata da versão "v0" de API para PSC.</p><p class="dou-paragraph" >Exemplo de URI-base:</p><p class="dou-paragraph" ><em class="dou-em" >https://servico.provedor_de_servico.com.br/v0/</em></p><p class="dou-paragraph" >Obs.: O endereço<em class="dou-em" >servico.provedor_de_servico.com.br</em></p><p class="dou-paragraph" >representa neste exemplo a porção authority da URI em domínio utilizado pelo PSC.</p><p class="dou-paragraph" >As demais porções de URI presentes neste documento devem ser concatenadas à URI-base.</p><p class="dou-paragraph" >6.4.3. Autorização e Autenticação para Requisição de Serviços</p><p class="dou-paragraph" >6.4.3.1. Fluxo básico para Uso de Serviços de Confiança</p><p class="dou-paragraph" >Seguindo o fluxo de autorização estabelecido pela RFC 6749, o uso de chaves privadas em PSC deverá ser precedido de solicitação bem-sucedida, por parte de aplicações, dos seguintes serviços:</p><p class="dou-paragraph" >i. Requisição de Código de Autorização</p><p class="dou-paragraph" >ii. Requisição de Token de Acesso</p><p class="dou-paragraph" >iii. Serviço de assinatura utilizando chave de usuários:</p><p class="dou-paragraph" >6.4.3.2. Trânsito de Fatores de Autenticação</p><p class="dou-paragraph" >As aplicações não deverão coletar fatores de autenticação do usuário. Para este fim, os PSC deverão se comunicar diretamente com equipamento do usuário, previamente identificado e cadastrado junto ao PSC de forma segura.</p><p class="dou-paragraph" >Excetua-se desta regra o Serviço "Autorização com Credenciais do Titular".</p><p class="dou-paragraph" >6.4.3.3. Autenticação de Aplicações de Assinatura</p><p class="dou-paragraph" >Para obter acesso aos serviços de confiança, os PSC deverão implementar obrigatoriamente o Serviço de Cadastro de Aplicação com Certificado ICP Brasil para SSL.</p><p class="dou-paragraph" >O PSC poderá também implementar Serviços de Confiança Opcionais para Cadastro de Aplicação sem Certificado, Token de Acesso para Aplicações e Manutenção de Aplicações.</p><p class="dou-paragraph" >Os PSC poderão implementar, para as aplicações, outros métodos de acesso aos seus serviços, desde que os riscos associados sejam avaliados e possibilitem rastreabilidade.</p><p class="dou-paragraph" >6.4.4. Relação de Serviços de Confiança Disponibilizados por PSC</p><p class="dou-paragraph" >a) Serviços de Confiança Obrigatórios</p><p class="dou-paragraph" >i. Código de Autorização</p><p class="dou-paragraph" >ii. Token de Acesso</p><p class="dou-paragraph" >iii. Assinatura</p><p class="dou-paragraph" >iv. Cadastro de Aplicação com Certificado</p><p class="dou-paragraph" >b) Serviços de Confiança Opcionais</p><p class="dou-paragraph" >i. Cadastro de Aplicação sem Certificado</p><p class="dou-paragraph" >ii. Token de Acesso para Aplicação</p><p class="dou-paragraph" >iii. Manutenção de Aplicação</p><p class="dou-paragraph" >iv. Autorização com Credenciais do Titular</p><p class="dou-paragraph" >6.4.5. Detalhamento de Serviços de Confiança Obrigatórios</p><p class="dou-paragraph" >6.4.5.1. Serviços de Autorização</p><p class="dou-paragraph" >6.4.5.1.1. Código de Autorização (Authorization Code Request)</p><p class="dou-paragraph" >Serviço para obter do titular a autorização de uso da sua chave privada.</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >.Path : &lt;URI-base&gt;/oauth/authorize;</p><p class="dou-paragraph" >.Método HTTPS : GET;</p><p class="dou-paragraph" >.Parâmetros da requisição: concatenados após o Path como parâmetros http query, usando o formato "application/x-www-form-urlencoded":</p><p class="dou-paragraph" >.response_type : obrigatório, valor "code";</p><p class="dou-paragraph" >.client_id : obrigatório, deve conter a identificação da aplicação;</p><p class="dou-paragraph" >.redirect_uri : opcional, deve ter a URI para redirecionar o usuário de volta para a aplicação de origem. A URI deve estar na lista de URI's autorizadas para a aplicação. Deve ser URL ENCODED. Se não informado, será considerada a primeira URI cadastrada para a aplicação;</p><p class="dou-paragraph" >.state : opcional, é retornado sem modificações para aplicação de origem;</p><p class="dou-paragraph" >.<em class="dou-em" >Recomendado. Um valor opaco usado pela aplicação para manter o estado entre a requisição e a resposta. O serviço de autorização incluirá este valor ao redirecionar o módulo do usuário de volta ao endereço da aplicação. Este parâmetro deverá ser usado para prevenir ataques de falsificação de requisições entre sites (cross-site request forgery).</em></p><p class="dou-paragraph" >.lifetime : opcional, indica o tempo de vida desejado para o token a ser gerado. Inteiro, em segundos;</p><p class="dou-paragraph" >.scope : opcional, se não informado, será considerado "single_signature".</p><p class="dou-paragraph" >(ver lista de escopos abaixo). Possíveis valores para o parâmetro:</p><p class="dou-paragraph" >.<strong class="dou-strong" >single_signature</strong>: token que permite a assinatura de apenas um conteúdo (hash), sendo invalidado apos a sua utilização;</p><p class="dou-paragraph" >.multi_signature: token que permite a assinatura de multiploshashes em uma única requisicao, sendo invalidado apos a sua utilização;</p><p class="dou-paragraph" >.signature_session: token de sessão OAuth que permite várias assinaturas em várias chamadas a API, desde que o token esteja dentro do prazo de validade ou que não tenha sido revogado pela aplicação ou pelo usuário.</p><p class="dou-paragraph" >.code_challenge : obrigatório, ver RFC 7636</p><p class="dou-paragraph" >.code_challenge_method : obrigatório, valor "S256" (ver RFC 7636).</p><p class="dou-paragraph" >b) Resposta da Requisição de Código de Autorização:</p><p class="dou-paragraph" >É retornado um URI de redirecionamento com dois parâmetros http query, usando o formato "application/x-www-form-urlencoded":</p><p class="dou-paragraph" >.code : obrigatório, código de autorização gerado pelo PSC, a ser usado na solicitação do token de acesso;</p><p class="dou-paragraph" >.state : obrigatório caso tenha sido informado na requisição, deverá conter o que foi enviado na requisição.</p><p class="dou-paragraph" >6.4.5.1.2. Token de Acesso</p><p class="dou-paragraph" >Após a obtenção de código de autorização, o token de acesso deve ser solicitado com parâmetros no formato "application/x-www-form-urlencoded" .</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >.Path : &lt;URI-base&gt;/oauth/token ;</p><p class="dou-paragraph" >.Método HTTPS : POST;</p><p class="dou-paragraph" >.Parâmetros da requisição : formato "application/x-www-formurlencoded"</p><p class="dou-paragraph" >.grant_type : obrigatório, valor "authorization_code";</p><p class="dou-paragraph" >.client_id : obrigatório, deve conter a identificação da aplicação;</p><p class="dou-paragraph" >.client_secret : opcional, sendo obrigatório se a aplicação não utilizar certificado ICP-Brasil;</p><p class="dou-paragraph" >.code : deve conter código de autorização retornado do Serviço Código de Autorização como redirect_uri;</p><p class="dou-paragraph" >.redirect_uri : opcional, deve ser igual ao informado no Serviço Código de Autorização;</p><p class="dou-paragraph" >.code_verifier : obrigatório, correspondendo a code_challenge enviado na Requisição de Código de Autorização, ver RFC 7636.</p><p class="dou-paragraph" >Exemplo:</p><p class="dou-paragraph" >POST {.../oauth/token} HTTP/1.1</p><p class="dou-paragraph" >Host: {servidor do PSC}</p><p class="dou-paragraph" ><em class="dou-em" >Content-Type: application/x-www-form-urlencoded</em></p><p class="dou-paragraph" ><em class="dou-em" >grant_type=authorization_code</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp;client_id=MyApplicationId</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp;client_secret=123qwe</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp; code=09b30f74d40a7fece1a26cccc97746c364e61022</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp; redirect_uri=https://idg.receita.fazenda.gov.br</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp; code_verifier={Verifier}</em></p><p class="dou-paragraph" >b) Resposta da Requisição de Token de Acesso:</p><p class="dou-paragraph" >.Parâmetros de retorno : formato "application/json;charset=UTF-8"</p><p class="dou-paragraph" >.access_token : obrigatório, valor do token de acesso;</p><p class="dou-paragraph" >.token_type : obrigatório, valor "Bearer";</p><p class="dou-paragraph" >.expires_in : obrigatório, valor inteiro com validade do token em segundos. Não deve ultrapassar o valor 300 (5 minutos);</p><p class="dou-paragraph" >.scope : opcional, deve ser informado se o escopo retornado for diferente do solicitado pela aplicação.</p><p class="dou-paragraph" >Exemplo:</p><p class="dou-paragraph" ><em class="dou-em" >HTTP/1.1 200 OK Content-Type: application/json;charset=UTF-8 Cache-Control: no-store Pragma: no-cache { "access_token": "b923575f1ced0ee732ee274b2e02784040bd9606", "expires_in": 300, "token_type": "Bearer" }</em></p><p class="dou-paragraph" >OBS: Não será permitido o refresh_token.</p><p class="dou-paragraph" >6.4.5.2. Assinatura</p><p class="dou-paragraph" >Os parâmetros com conteúdo a ser assinado e assinaturas deverão conter valores em hexadecimal.</p><p class="dou-paragraph" >Se o escopo do token permitir apenas uma assinatura (sigle_signature) e for informado mais de um conteúdo, uma mensagem de erro deve ser retornada.</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >.Path : &lt;URI-base&gt;/oauth/signature</p><p class="dou-paragraph" >.Método HTTPS : POST</p><p class="dou-paragraph" >.Cabeçalho :</p><p class="dou-paragraph" >.Content-type : application/json ;</p><p class="dou-paragraph" >.Accept : application/json ;</p><p class="dou-paragraph" >.Authorization : Bearer<em class="dou-em" >access_token;</em></p><p class="dou-paragraph" >.Parâmetros : formato "application/json;charset=UTF-8" :</p><p class="dou-paragraph" >.certificate_alias": identificador da chave ;</p><p class="dou-paragraph" >.hashes : conjunto com valores a serem assinados. Cada elemento do conjunto conterá:</p><p class="dou-paragraph" >.id: identificador do conteúdo a ser assinado;</p><p class="dou-paragraph" >.alias: forma legível do identificador do conteúdo;</p><p class="dou-paragraph" >.hash: conteúdo a ser assinado</p><p class="dou-paragraph" >Exemplo</p><p class="dou-paragraph" ><em class="dou-em" >"certificate_alias": "cert001abc",</em></p><p class="dou-paragraph" ><em class="dou-em" >"hashes": [{</em></p><p class="dou-paragraph" ><em class="dou-em" >"id": "Signature request ID 1",</em></p><p class="dou-paragraph" ><em class="dou-em" >"alias": "Contrato de aluguel XPTO",</em></p><p class="dou-paragraph" ><em class="dou-em" >"hash": "hash to sign"</em></p><p class="dou-paragraph" ><em class="dou-em" >},</em></p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" ><em class="dou-em" >"id": "Signature request ID 2",</em></p><p class="dou-paragraph" ><em class="dou-em" >"alias": "Documento do Word",</em></p><p class="dou-paragraph" ><em class="dou-em" >"hash": "hash to sign"</em></p><p class="dou-paragraph" ><em class="dou-em" >}</em></p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" ><em class="dou-em" >"id": "Signature request ID n",</em></p><p class="dou-paragraph" ><em class="dou-em" >"alias": "Firefox",</em></p><p class="dou-paragraph" ><em class="dou-em" >"hash": "hash to sign"</em></p><p class="dou-paragraph" ><em class="dou-em" >}</em></p><p class="dou-paragraph" ><em class="dou-em" >]}</em></p><p class="dou-paragraph" >b) Resposta da Requisição de Assinatura:</p><p class="dou-paragraph" >.Parâmetros : formato "application/json;charset=UTF-8" :</p><p class="dou-paragraph" >.status : obrigatório, "success" para sucesso;</p><p class="dou-paragraph" >.message: obrigatório, mensagem com informações adicionais;</p><p class="dou-paragraph" >.id : identificador do conteúdo assinado;</p><p class="dou-paragraph" >.raw_signature : valor numérico em base64 da assinatura produzida.</p><p class="dou-paragraph" >Exemplo</p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" ><em class="dou-em" >"status": "success",</em></p><p class="dou-paragraph" ><em class="dou-em" >"message": "Hashes assinados com sucesso",</em></p><p class="dou-paragraph" ><em class="dou-em" >"signatures": [{</em></p><p class="dou-paragraph" ><em class="dou-em" >"id": "Signature request ID 1",</em></p><p class="dou-paragraph" ><em class="dou-em" >"raw_signature": "my raw signature base64"</em></p><p class="dou-paragraph" ><em class="dou-em" >},</em></p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" ><em class="dou-em" >"id": "Signature request ID 2",</em></p><p class="dou-paragraph" ><em class="dou-em" >"raw_signature": "my raw signature base64"</em></p><p class="dou-paragraph" ><em class="dou-em" >},</em></p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" ><em class="dou-em" >"id": "Signature request ID n",</em></p><p class="dou-paragraph" ><em class="dou-em" >"raw_signature": "my raw signature base64"</em></p><p class="dou-paragraph" ><em class="dou-em" >}]}</em></p><p class="dou-paragraph" >6.4.5.4. Cadastro de Aplicação com Certificado</p><p class="dou-paragraph" >Serviço para cadastro de uma aplicação junto ao PSC, sendo que a aplicação utilizará um certificado SSL ICP-Brasil para assinar os dados enviados, substituindo neste caso o Serviço de Cadastro de Aplicação.</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >.Path : &lt;URI-base&gt;/oauth/application_cert</p><p class="dou-paragraph" >.Método HTTPS: POST</p><p class="dou-paragraph" >.Cabeçalho :</p><p class="dou-paragraph" >.Content-type : application/json ;</p><p class="dou-paragraph" >.Accept : application/json ;</p><p class="dou-paragraph" >.Parâmetros : formato "application/json;charset=UTF-8" :</p><p class="dou-paragraph" >.signed_info, estrutura de dados assinada com certificado SSL ICPBrasil, contendo:</p><p class="dou-paragraph" >.name, obrigatório, nome da aplicação;</p><p class="dou-paragraph" >.comments, obrigatório, descrição da aplicação;</p><p class="dou-paragraph" >.redirect_uris, obrigatório, URI's autorizadas para redirecionamento (para serviços de requisição de autorização). Devem ser oriundas da URL Base do certificado de equipamento apresentado, sendo vedada a utilização de fragments<em class="dou-em" >;</em></p><p class="dou-paragraph" >b) Resposta do Serviço de Cadastro de Aplicação com Certificado</p><p class="dou-paragraph" >.Parâmetros : formato "application/json;charset=UTF-8" :</p><p class="dou-paragraph" >.status, obrigatório, "success" para sucesso;</p><p class="dou-paragraph" >.message,<em class="dou-em" >obrigatório, mensagem com informações adicionais.</em></p><p class="dou-paragraph" ><em class="dou-em" >Exemplo:</em></p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" >.<em class="dou-em" >"status": "success",</em></p><p class="dou-paragraph" >.<em class="dou-em" >"message": "Aplicacao cadastrada com sucesso"</em></p><p class="dou-paragraph" ><em class="dou-em" >}</em></p><p class="dou-paragraph" >6.4.6.2. Serviços de Manutenção de Cadastro de Aplicação Serviço para manutenção das informações armazenadas de uma aplicação no PSC.</p><p class="dou-paragraph" >É obrigatório para todas as aplicações que utilizarem serviços de autorização não identificadas por certificados ICP-Brasil para SSL.</p><p class="dou-paragraph" >6.4.6.2.1. Token de Acesso para Aplicação Requisição para que uma aplicação obtenha token de acesso para manutenção de seu cadastro junto ao PSC.</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >.Método HTTPS : POST;</p><p class="dou-paragraph" >.Path : &lt;URI-base&gt;/oauth/client_token ;</p><p class="dou-paragraph" >.Parâmetros da requisição: concatenados após o Path como parâmetros http query, usando o formato "application/x-www-form-urlencoded":</p><p class="dou-paragraph" >.grant_type, obrigatório, valor "client_credentials";</p><p class="dou-paragraph" >.client_id, obrigatório, deve conter a identificação da aplicação;</p><p class="dou-paragraph" >.client_secret, obrigatório se a aplicação não utilizar certificado SSL ICP-Brasil;</p><p class="dou-paragraph" >.lifetime, opcional, validade desejada para o token a ser gerado, deve conter valor Inteiro, em segundos.</p><p class="dou-paragraph" >Exemplo</p><p class="dou-paragraph" ><em class="dou-em" >POST {.../oauth/client_token} HTTP/1.1</em></p><p class="dou-paragraph" ><em class="dou-em" >Host: {servidor do PSC}</em></p><p class="dou-paragraph" ><em class="dou-em" >Content-Type: application/x-www-form-urlencoded</em></p><p class="dou-paragraph" ><em class="dou-em" >client_id=Identificacao_aplicacao</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp;client_secret=123qwe</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp;grant_type=client_credentials</em></p><p class="dou-paragraph" ><em class="dou-em" >&amp;lifetime=900</em></p><p class="dou-paragraph" >b) Resposta da Requisição de Token de Acesso para Aplicações:</p><p class="dou-paragraph" >.Parâmetros de retorno : formato "application/json;charset=UTF-8" :</p><p class="dou-paragraph" >.access_token, obrigatório, valor do token de acesso;</p><p class="dou-paragraph" >.oken_type, obrigatório, valor "Bearer";</p><p class="dou-paragraph" >.expires_in, opcional, validade do token em segundos.</p><p class="dou-paragraph" >Exemplo:</p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" ><em class="dou-em" >"access_token": "b923575f1ced0ee732ee274b2e02784040bd9606",</em></p><p class="dou-paragraph" ><em class="dou-em" >"expires_in": 7200, "</em></p><p class="dou-paragraph" ><em class="dou-em" >token_type": "Bearer"</em></p><p class="dou-paragraph" >}</p><p class="dou-paragraph" >6.4.6.2.2. Manutenção de Aplicação</p><p class="dou-paragraph" >Serviço para atualização de informações de uma aplicação. Requer um token de acesso para aplicações, enviado no parâmetro de cabeçalho "Authorization" .</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >.Path : &lt;URI-base&gt;/oauth/client_maintenance ;</p><p class="dou-paragraph" >.Método HTTPS : PUT ;</p><p class="dou-paragraph" >.Cabeçalho :</p><p class="dou-paragraph" >.Content-type : application/json ;</p><p class="dou-paragraph" >.Accept : application/json ;</p><p class="dou-paragraph" >.Authorization : Bearer<em class="dou-em" >access_token ("Bearer" concatenado espaço e access_token);</em></p><p class="dou-paragraph" >.Parâmetros : formato "application/json;charset=UTF-8" :</p><p class="dou-paragraph" >.client_id, obrigatório, CNPJ base da aplicacao (antes da "/");</p><p class="dou-paragraph" >.client_secret, opcional, nova senha da aplicacao;</p><p class="dou-paragraph" >.name, opcional, nome da aplicação;</p><p class="dou-paragraph" >.comments, opcional, observações gerais de uso da aplicação;</p><p class="dou-paragraph" >.redirect_uris, opcional, URI's autorizadas para redirecionamento (para requisição de código de autorização).</p><p class="dou-paragraph" >Exemplo:</p><p class="dou-paragraph" ><em class="dou-em" >{</em></p><p class="dou-paragraph" ><em class="dou-em" >"client_id": "(CNPJ da aplicacao)",</em></p><p class="dou-paragraph" ><em class="dou-em" >"client_secret": "(Senha/Segredo da aplicacao)",</em></p><p class="dou-paragraph" ><em class="dou-em" >"name": "(Nome/Descricao da aplicacao)",</em></p><p
