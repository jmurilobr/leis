# INSTRUÇÃO NORMATIVA Nº 2, DE 12 DE MARÇO DE 2019

<div class="texto-dou"><p class="dou-paragraph" ></p><p class="identifica"><strong class="dou-strong" >INSTRUÇÃO NORMATIVA Nº 2, DE 12 DE MARÇO DE 2019</strong></p><p class="ementa">Atualiza requisitos para serviços de confiança de uso de chaves criptográficas e inclui a definição da Lista de Prestadores de Serviço de Confiança - LPSC no âmbito da ICP-Brasil.</p><p class="dou-paragraph" ><strong class="dou-strong" >O DIRETOR-PRESIDENTE DO INSTITUTO NACIONAL DE TECNOLOGIA DA INFORMAÇÃO,</strong>no uso das atribuições que lhe foram conferidas pelo inciso VI do art. 9º do anexo I do Decreto nº 8.985, de 8 de fevereiro de 2017, e pelo art. 1º da Resolução nº 33 do Comitê Gestor da ICP-Brasil, de 21 de outubro de 2004, resolve:</p><p class="dou-paragraph" >Art. 1º O item 6.4 do DOC-ICP-17.01, versão 1.1, passa a vigorar com a seguinte redação:</p><p class="dou-paragraph" >"................................................................................................................................</p><p class="dou-paragraph" >6.4. Requisitos para serviços de confiança de uso de chaves privadas</p><p class="dou-paragraph" >6.4.1. Definições para Interface de Serviços de Confiança</p><p class="dou-paragraph" >Deverá ser utilizado o protocolo TLS, definido pela RFC 5246 ou a versão</p><p class="dou-paragraph" >atualizada, para comunicação com serviços de confiança.</p><p class="dou-paragraph" >Deverá ser utilizado o framework OAuth 2.0 (RFC 6749 e RFC 7636) para</p><p class="dou-paragraph" >implementação da interface aos serviços de confiança dos PSC.</p><p class="dou-paragraph" >Adicionalmente, poderá ser implementada outra interface para os serviços de</p><p class="dou-paragraph" >confiança, desde que o PSC proveja o software necessário para possibilitar ao</p><p class="dou-paragraph" >titular o uso das suas chaves privadas de forma segura.</p><p class="dou-paragraph" >6.4.2. Definições para URI de base para Serviços de Confiança</p><p class="dou-paragraph" >A URI de base - URI-base - definirá o estilo e formato dos endereços HTTPS de</p><p class="dou-paragraph" >serviços de confiança.</p><p class="dou-paragraph" >A URI de base conterá número correspondendo à versão de API definida pela</p><p class="dou-paragraph" >ICP-Brasil.</p><p class="dou-paragraph" >Este documento trata da versão "v0" de API para PSC.</p><p class="dou-paragraph" >Exemplo de URI-base:</p><p class="dou-paragraph" ><em class="dou-em" >https://servico.provedor_de_servico.com.br/v0/</em></p><p class="dou-paragraph" >Obs.: O endereço<em class="dou-em" >servico.provedor_de_servico.com.br</em>representa neste exemplo</p><p class="dou-paragraph" >a porção authority da URI em domínio utilizado pelo PSC.</p><p class="dou-paragraph" >As demais porções de URI presentes neste documento devem ser concatenadas</p><p class="dou-paragraph" >à URI-base.</p><p class="dou-paragraph" >6.4.3. Autorização e Autenticação para Requisição de Serviços</p><p class="dou-paragraph" >6.4.3.1. Fluxo básico para Uso de Serviços de Confiança</p><p class="dou-paragraph" >Seguindo o fluxo de autorização estabelecido pela RFC 6749, o uso de chaves</p><p class="dou-paragraph" >privadas em PSC deverá ser precedido de solicitação bem-sucedida, por parte de</p><p class="dou-paragraph" >aplicações, dos seguintes serviços:</p><p class="dou-paragraph" >i. Requisição de Código de Autorização</p><p class="dou-paragraph" >ii. Requisição de Token de Acesso</p><p class="dou-paragraph" >iii. Serviço de assinatura utilizando chave de usuários:</p><p class="dou-paragraph" >6.4.3.2. Trânsito de Fatores de Autenticação</p><p class="dou-paragraph" >As aplicações não deverão coletar fatores de autenticação do usuário. Para este</p><p class="dou-paragraph" >fim, os PSC deverão se comunicar diretamente com equipamento do usuário,</p><p class="dou-paragraph" >previamente identificado e cadastrado junto ao PSC de forma segura.</p><p class="dou-paragraph" >Excetua-se desta regra o Serviço "Autorização com Credenciais do Titular".</p><p class="dou-paragraph" >6.4.3.3. Autenticação de Aplicações de Assinatura</p><p class="dou-paragraph" >Para obter acesso aos serviços de confiança, os PSC deverão implementar</p><p class="dou-paragraph" >obrigatoriamente o Serviço de Cadastro de Aplicação com Certificado ICP-Brasil</p><p class="dou-paragraph" >para SSL.</p><p class="dou-paragraph" >O PSC poderá também implementar Serviços de Confiança Opcionais para</p><p class="dou-paragraph" >Cadastro de Aplicação sem Certificado, Token de Acesso para Aplicações e</p><p class="dou-paragraph" >Manutenção de Aplicações.</p><p class="dou-paragraph" >Os PSC poderão implementar, para as aplicações, outros métodos de acesso aos</p><p class="dou-paragraph" >seus serviços, desde que os riscos associados sejam avaliados e possibilitem</p><p class="dou-paragraph" >rastreabilidade.</p><p class="dou-paragraph" >6.4.4. Relação de Serviços de Confiança Disponibilizados por PSC</p><p class="dou-paragraph" >a) Serviços de Confiança Obrigatórios</p><p class="dou-paragraph" >i. Código de Autorização</p><p class="dou-paragraph" >ii. Token de Acesso</p><p class="dou-paragraph" >iii. Assinatura</p><p class="dou-paragraph" >iv. Cadastro de Aplicação com Certificado</p><p class="dou-paragraph" >v. Listagem de Certificados do Titular</p><p class="dou-paragraph" >vi. Localização de Titular</p><p class="dou-paragraph" >b) Serviços de Confiança Opcionais</p><p class="dou-paragraph" >i. Cadastro de Aplicação sem Certificado</p><p class="dou-paragraph" >ii. Token de Acesso para Aplicação</p><p class="dou-paragraph" >iii. Manutenção de Aplicação</p><p class="dou-paragraph" >iv. Autorização com Credenciais do Titular</p><p class="dou-paragraph" >6.4.5. Detalhamento de Serviços de Confiança Obrigatórios</p><p class="dou-paragraph" >6.4.5.1. Serviços de Autorização</p><p class="dou-paragraph" >6.4.5.1.1. Código de Autorização (Authorization Code Request)</p><p class="dou-paragraph" >Serviço para obter do titular a autorização de uso da sua chave privada.</p><p class="dou-paragraph" >Caso o titular possua mais de um certificado, o PSC deverá apresentá-los para</p><p class="dou-paragraph" >que o titular faça a escolha no mesmo contexto de aplicação em que</p><p class="dou-paragraph" >transitarem os fatores de autenticação.</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >Path : &lt;URI-base&gt;/oauth/authorize;</p><p class="dou-paragraph" >Método HTTPS: GET;</p><p class="dou-paragraph" >Parâmetros da requisição: concatenados após o Path como parâmetros http</p><p class="dou-paragraph" >query, usando o formato "application/x-www-form-urlencoded":</p><p class="dou-paragraph" >response_type: obrigatório, valor "code";</p><p class="dou-paragraph" >client_id: obrigatório, deve conter a identificação da aplicação;</p><p class="dou-paragraph" >redirect_uri: opcional, deve ter a URI para redirecionar o usuário de volta para a</p><p class="dou-paragraph" >aplicação de origem. A URI deve estar na lista de URI's autorizadas para a aplicação.</p><p class="dou-paragraph" >Deve ser URL ENCODED. Se não informado, será considerada a primeira URI</p><p class="dou-paragraph" >cadastrada para a aplicação;</p><p class="dou-paragraph" >state: opcional, é retornado sem modificações para aplicação de origem;</p><p class="dou-paragraph" >Recomendado. Um valor opaco usado pela aplicação para manter o estado entre a</p><p class="dou-paragraph" >requisição e a resposta. O serviço de autorização incluirá este valor ao redirecionar o</p><p class="dou-paragraph" >módulo do usuário de volta ao endereço da aplicação. Este parâmetro deverá ser</p><p class="dou-paragraph" >usado para prevenir ataques de falsificação de requisições entre sites (cross-site</p><p class="dou-paragraph" >request forgery).</p><p class="dou-paragraph" >lifetime: opcional, indica o tempo de vida desejado para o token a ser gerado. Inteiro,</p><p class="dou-paragraph" >em segundos;</p><p class="dou-paragraph" >scope: opcional, se não informado, será considerado "single_signature".</p><p class="dou-paragraph" >(ver lista de escopos abaixo). Possíveis valores para o parâmetro:</p><p class="dou-paragraph" ><strong class="dou-strong" >single_signature</strong>: token que permite a assinatura de apenas um conteúdo (hash),</p><p class="dou-paragraph" >sendo invalidado apos a sua utilização;</p><p class="dou-paragraph" ><strong class="dou-strong" >multi_signature</strong>: token que permite a assinatura de multiplos hashes em uma única</p><p class="dou-paragraph" >requisicao, sendo invalidado apos a sua utilização;</p><p class="dou-paragraph" ><strong class="dou-strong" >signature_session</strong>: token de sessão OAuth que permite várias assinaturas em várias</p><p class="dou-paragraph" >chamadas a API, desde que o token esteja dentro do prazo de validade ou que não</p><p class="dou-paragraph" >tenha sido revogado pela aplicação ou pelo usuário.</p><p class="dou-paragraph" >code_challenge: obrigatório, ver RFC 7636</p><p class="dou-paragraph" >code_challenge_method: obrigatório, valor "S256" (ver RFC 7636).</p><p class="dou-paragraph" >login_hint: opcional, valor de CPF ou CNPJ a ser informado como filtro para seleção</p><p class="dou-paragraph" >do certificado a ser utilizado.</p><p class="dou-paragraph" >b) Resposta da Requisição de Código de Autorização:</p><p class="dou-paragraph" >Se o usuário autorizar a solicitação, o PSC emite um código de autorização com</p><p class="dou-paragraph" >tempo de validade curto e retorna para aplicação cliente com uma URI de</p><p class="dou-paragraph" >redirecionamento contendo parâmetros no componente http query, usando o</p><p class="dou-paragraph" >formato "application/x-www-form-urlencoded":</p><p class="dou-paragraph" >code: obrigatório, código de autorização gerado pelo PSC, a ser usado na solicitação do</p><p class="dou-paragraph" >token de acesso;</p><p class="dou-paragraph" >state: obrigatório caso tenha sido informado na requisição, deverá conter o</p><p class="dou-paragraph" >que foi enviado na requisição.</p><p class="dou-paragraph" >Se o usuário não autorizar a solicitação, o PSC retorna para aplicação cliente</p><p class="dou-paragraph" >através de sua redirect_uri os seguintes parâmetros via http query, usando o</p><p class="dou-paragraph" >formato "application/x-www-form-urlencoded":</p><p class="dou-paragraph" >error: obrigatório, com o valor "user_denied";</p><p class="dou-paragraph" >state: obrigatório caso tenha sido informado na requisição, deverá conter o que foi enviado</p><p class="dou-paragraph" >na requisição.</p><p class="dou-paragraph" >6.4.5.1.2. Token de Acesso</p><p class="dou-paragraph" >Após a obtenção de código de autorização, o token de acesso deve ser</p><p class="dou-paragraph" >solicitado com parâmetros no formato "application/x-www-form-urlencoded".</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >Path : &lt;URI-base&gt;/oauth/token;</p><p class="dou-paragraph" >Método HTTPS: POST;</p><p class="dou-paragraph" >Parâmetros da requisição: formato "application/x-www-form-urlencoded"</p><p class="dou-paragraph" >grant_type: obrigatório, valor "authorization_code";</p><p class="dou-paragraph" >client_id: obrigatório, deve conter a identificação da aplicação;</p><p class="dou-paragraph" >client_secret: obrigatório, deve conter o segredo associado à aplicação;</p><p class="dou-paragraph" >code: obrigatório, deve conter código de autorização retornado do Serviço Código de</p><p class="dou-paragraph" >Autorização;</p><p class="dou-paragraph" >redirect_uri: opcional, deve ser igual ao informado no Serviço Código de Autorização;</p><p class="dou-paragraph" >code_verifier: obrigatório, correspondendo a code_challenge enviado na Requisição</p><p class="dou-paragraph" >de Código de Autorização, ver RFC 7636.</p><p class="dou-paragraph" >Exemplo:</p><p class="dou-paragraph" ><em class="dou-em" >POST {.../oauth/token} HTTP/1.1</em></p><p class="dou-paragraph" >Host: {servidor do PSC}</p><p class="dou-paragraph" >Content-Type: application/x-www-form-urlencoded</p><p class="dou-paragraph" >grant_type=authorization_code</p><p class="dou-paragraph" >&amp;client_id=MyApplicationId</p><p class="dou-paragraph" >&amp;client_secret=123qwe</p><p class="dou-paragraph" >&amp;code=09b30f74d40a7fece1a26cccc97746c364e61022</p><p class="dou-paragraph" >&amp;redirect_uri=https://idg.receita.fazenda.gov.br</p><p class="dou-paragraph" >&amp;code_verifier={Verifier}</p><p class="dou-paragraph" >b) Resposta da Requisição de Token de Acesso:</p><p class="dou-paragraph" >Se a requisição é valida e autorizada o PSC emite um token de acesso e retorna</p><p class="dou-paragraph" >a requisição com sucesso, via HTTP Status Code 200.</p><p class="dou-paragraph" >Parâmetros de retorno: formato "application/json;charset=UTF-8"</p><p class="dou-paragraph" >access_token: obrigatório, valor do token de acesso;</p><p class="dou-paragraph" >token_type: obrigatório, valor "Bearer";</p><p class="dou-paragraph" >expires_in: obrigatório, valor inteiro com validade do token em</p><p class="dou-paragraph" >segundos.Para acesso a objeto de pessoas físicas não deve</p><p class="dou-paragraph" >ultrapassar (7 dias), sendo que para pessoas jurídicas este limite será</p><p class="dou-paragraph" >de (30 dias);</p><p class="dou-paragraph" >scope: opcional, deve ser informado se o escopo retornado for</p><p class="dou-paragraph" >diferente do solicitado pela aplicação;</p><p class="dou-paragraph" >authorized_idetification_type: obrigatório, deverá conter "CPF" ou</p><p class="dou-paragraph" >"CNPJ"</p><p class="dou-paragraph" >authorized_idetification: obrigatório, valor correspondendo ao CPF ou</p><p class="dou-paragraph" >CNPJ associado ao titular do certificado.</p><p class="dou-paragraph" >Exemplo:</p><p class="dou-paragraph" ><em class="dou-em" >HTTP/1.1 200</em></p><p class="dou-paragraph" >OK</p><p class="dou-paragraph" >Content-Type: application/json;charset=UTF-8</p><p class="dou-paragraph" >Cache-Control: no-store</p><p class="dou-paragraph" >Pragma: no-cache</p><p class="dou-paragraph" >{ "</p><p class="dou-paragraph" >access_token": "</p><p class="dou-paragraph" >b923575f1ced0ee732ee274b2e02784040bd9606",</p><p class="dou-paragraph" >"expires_in": 300,</p><p class="dou-paragraph" >"token_type": "Bearer</p><p class="dou-paragraph" >"authorized_identification_type": "CPF</p><p class="dou-paragraph" >"authorized_identification": 00000000001</p><p class="dou-paragraph" >}</p><p class="dou-paragraph" >OBS: Não será permitido o refresh_token.</p><p class="dou-paragraph" >Se a requisição não for válida, houver falha na autenticação da aplicação cliente</p><p class="dou-paragraph" >ou alguma outra falha, o PSC retorna a requisição com erro, via HTTP Status</p><p class="dou-paragraph" >Code de erro correspondente à situação ocorrida via JSON com os seguintes</p><p class="dou-paragraph" >parâmetros:</p><p class="dou-paragraph" >Parâmetros de retorno: formato "application/json;charset=UTF-8":</p><p class="dou-paragraph" >error: obrigatório, representa o código do erro. Possíveis valores para o</p><p class="dou-paragraph" >parâmetro e HTTP Status Code de erro:</p><p class="dou-paragraph" >invalid_request: HTTP Status Code 400, ocorre quando algum</p><p class="dou-paragraph" >parâmetro obrigatório não tiver sido informado ou inclui um valor de</p><p class="dou-paragraph" >parâmetro não suportado ou algum parâmetro com valor duplicado</p><p class="dou-paragraph" >informado ou a requisição é mal formada;</p><p class="dou-paragraph" >invalid_grant: HTTP Status Code 400, ocorre quando o código de</p><p class="dou-paragraph" >autorização apresentado estiver inválido ou expirado ou tiver sido</p><p class="dou-paragraph" >emitido para uma outra aplicação cliente diferente da informada ou já</p><p class="dou-paragraph" >estiver sido utilizado em um cenário de uso único(scope</p><p class="dou-paragraph" >single_signature e multi_signature). Ocorre também na validação da</p><p class="dou-paragraph" >redirect_uri e na validação do code_verifier(ver RFC 7636);</p><p class="dou-paragraph" >invalid_client: HTTP Status Code 401, ocorre quando houver falha na</p><p class="dou-paragraph" >autenticação da aplicação cliente, desde aplicação não identificada até</p><p class="dou-paragraph" >credenciais inválidas;</p><p class="dou-paragraph" >unsupported_grant_type: HTTP Status Code 400, ocorre quando o valor</p><p class="dou-paragraph" >informado no parâmetro grant_type não for suportado.</p><p class="dou-paragraph" >server_error: HTTP Status Code 500, ocorre quando houver algum erro</p><p class="dou-paragraph" >interno não tratado pelo PSC.</p><p class="dou-paragraph" >error_description: opcional, texto com informações adicionais descrevendo</p><p class="dou-paragraph" >o erro a fim de assistir o entendimento do ocorrido;</p><p class="dou-paragraph" >error_uri: opcional, URI de uma página WEB que contém informações sobre</p><p class="dou-paragraph" >o erro ocorrido.</p><p class="dou-paragraph" >Exemplo:</p><p class="dou-paragraph" ><em class="dou-em" >HTTP/1.1 400 Bad Request</em></p><p class="dou-paragraph" >Content-Type: application/json;charset=UTF-8</p><p class="dou-paragraph" >Cache-Control: no-store</p><p class="dou-paragraph" >Pragma: no-cache</p><p class="dou-paragraph" >{</p><p class="dou-paragraph" >"<em class="dou-em" >error": "invalid_request",</em></p><p class="dou-paragraph" >"<em class="dou-em" >error_description": "Parâmetro obrigatório não informado: code",</em></p><p class="dou-paragraph" >"<em class="dou-em" >error_uri":"https://psc.exemplo.com.br/docs/oauth2-error#invalid_request"</em></p><p class="dou-paragraph" >}</p><p class="dou-paragraph" >6.4.5.2. Assinatura</p><p class="dou-paragraph" >Os parâmetros com conteúdo a ser assinado e assinaturas deverão conter</p><p class="dou-paragraph" >valores em Base64.</p><p class="dou-paragraph" >Se o escopo do token permitir apenas uma assinatura (single_signature) e for</p><p class="dou-paragraph" >informado mais de um conteúdo, uma mensagem de erro deve ser retornada.</p><p class="dou-paragraph" >a) Solicitação</p><p class="dou-paragraph" >Path: &lt;URI-base&gt;/oauth/signature</p><p class="dou-paragraph" >Método HTTPS: POST</p><p class="dou-paragraph" >Cabeçalho: Re: Nova Versão da IN PSC</p><p class="dou-paragraph" >Content-type: application/json;</p><p class="dou-paragraph" >Accept : application/json;</p><p class="dou-paragraph" >Authorization: Bearer<em class="dou-em" >access_token;</em></p><p class="dou-paragraph" >Parâmetros: formato "application/json;charset=UTF-8" :</p><p class="dou-paragraph" >hashes: conjunto com valores a serem assinados. Cada elemento do conjunto conterá:</p><p class="dou-paragraph" >id: identificador do conteúdo a ser assinado;</p><p class="dou-paragraph" >alias: forma legível do identificador do conteúdo;</p><p class="dou-paragraph" >hash: conteúdo a ser assinado;</p><p class="dou-paragraph" >certificate_alias: opcional, identificador do certificado correspondente à chave utilizada</p><p class="dou-paragraph" >na assinatura;</p><p class="dou-paragraph" >signature_format: obrigatório:</p><p class="dou-paragraph" >RAW: resultado direto (em base64) da operação RSA/DSA sobre o hash</p><p class="dou-paragraph" >informado na requisição.</p><p class="dou-paragraph" >CMS detached (PKCS#7), contendo os seguintes atributos assinados:</p><p class="dou-paragraph" >- contentType</p><p class="dou-paragraph" >- signingTime (hora do PSC)</p><p class="dou-paragraph" >- messageDigest (hash informado pela aplicação na</p><p class="dou-paragraph" >requisição)</p><p class="dou-paragraph" >- signingCertificateV2 (certificado do assinante)</p><p class="dou-paragraph" >Exemplo</p><p class="dou-paragraph" ><em class="dou-em" >"hashes": [{</em></p><p class="dou-paragraph" >"id": "Signature request ID 1",</p><p class="dou-paragraph" >"alias": "Contrato de aluguel XPTO",</p><p class="dou-paragraph" >"hash": "hash to sign",</p><p class="dou-paragraph" >"<em class="dou-em" >signature_format": "RAW"</em></p><p class="dou-paragraph" >},</p><p class="dou-paragraph" >{</p><p class="dou-paragraph" >"id": "Signature request ID 2",</p><p class="dou-paragraph" >"alias": "Documento do Word",</p><p class="dou-paragraph" >"hash": "hash to sign",</p><p class="dou-paragraph" >"<em class="dou-em" >signature_format": "CMS"</em></p><p class="dou-paragraph" >}</p><p class="dou-paragraph" >{</p><p class="dou-paragraph" >"id": "Signature request ID n",</p><p class="dou-paragraph" >"alias": "Firefox",</p><p class="dou-paragraph" >"hash": "hash to sign",</p><p class="dou-paragraph" >"<em class="dou-em" >signature_format" : "RAW"</em></p><p class="dou-paragraph" >}</p><p class="dou-paragraph" >]}</p><p class="dou-paragraph" >b) Resposta da Requisição de Assinatura:</p><p class="dou-paragraph" >O PSC retornará a requisição com sucesso, via HTTP Status Code 200.</p><p class="dou-paragraph" >Parâmetros: formato "application/json;charset=UTF-8":</p><p class="dou-paragraph" >certificate_alias: obrigatório, identificador do certificado</p><p class="dou-paragraph" >correspondente à chave utilizada na assinatura;</p><p class="dou-paragraph" >signatures: obrigatório, conjunto com identificadores dos conteúdos a</p><p class="dou-paragraph" >serem assinados e valores assinados.
